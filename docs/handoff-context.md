# Контекст проекта: мониторинг тележек + Magma

Документ для передачи в новый чат: что уже сделано, какие решения приняты, что дальше.

## 1. Что это

MVP системы мониторинга производственных тележек: веб-карта показывает положение тележек
на площадке. Отдельно исследуется развёртывание Magma (LTE-ядро) как источника данных
в будущем. Репозиторий: `6g-magama-mvp`, ветка `mvp`.

Ключевая мысль: **карта — наш продукт, Magma — потенциальный источник данных, а не интерфейс**.
NMS Magma не модифицируем.

## 2. Что уже работает

- Карта Leaflet с подложкой `.pmtiles`, станциями и тележками.
- Проигрывание записанного сценария: `FileReplaySource` + `ReplayClock`, зациклено.
- Живой режим: `PollingFileSource` опрашивает снимок раз в секунду (`/?source=live`).
- Устаревание: отметка старше 2.5 с гасится, в плашке «Устарело: N из M».
- Точность: круги `accuracyM`, цвет по методу (RSSI / ECID+TA / Cell ID / симуляция).
- Демо-продюсер: `npm run live` пишет `public/data/live-scenario.json` раз в секунду.
- Тесты: 63, все зелёные. Линт и сборка чистые.

## 3. Поток данных

```
продюсер / будущий ingest → ScenarioFile (JSON) → fetch раз в секунду
   → parseJsonScenario (zod) → PositionSource → карта Leaflet
```

Порт `PositionSource` (`start/stop/onFix/onReset/onHealth`) позволяет заменить источник
без изменения карты: сейчас файл, потом HTTP-эндпоинт или WebSocket.

## 4. Контракт данных

`ScenarioFile` (`schemaVersion: 1`):

- `site` — `coordinateSystem: local | wgs84`, `origin`, `basemap`;
- `stations[]` — базовые станции;
- `carts[]` — тележки (`id`, `name`, `color`, `imsi`);
- `fixes[]` — отметки: `cartId`, `ts` (ISO-8601 UTC), `position`, `accuracyM`, `method`,
  `stationsUsed`, `speedMps`, `headingDeg`, `truth`;
- `generatedAt?` — время сборки снимка (пишет продюсер).

Требования: точки в одной системе координат с площадкой; `cartId` существует в `carts`;
`method` из фиксированного списка. Файл меняется только вместе с `domain/types.ts`
и `domain/schemas.ts`.

## 5. Принятые решения

1. **Браузер не обращается к Magma напрямую.** Учётные данные ядра — только на сервере.
   Появится ingest, который читает API и пишет `ScenarioFile`.
2. **Magma не даёт координат.** Она даёт события (attach, сессия, handover) и привязку IMSI.
   Позиция считается по измерениям сигнала (RSSI/TA) — это отдельный слой.
3. **NMS не модифицируем.** Если нужен интерфейс — развиваем нашу карту.
4. **Карта — статика.** Ей не нужен Kubernetes; контейнер с nginx — по желанию.
5. **Charmed Magma не используем:** репозиторий архивирован в 2023, последний релиз
   бандла — май 2023. Живой путь — оригинальная Magma 1.8 через Helm.
6. **Устаревание — 2.5 с** (`STALE_AFTER_MS` в `domain/status.ts`), под частоту 1 Гц.

## 6. Словарь

- **eNodeB** — базовая станция (вышка).
- **AGW** — ядро на площадке: принимает модемы, выдаёт IP; нужны **два сетевых порта**
  (S1 к вышке, SGi в сеть); ставится на отдельную машину, не в Kubernetes.
- **Orc8r** — оркестратор: конфиги, сертификаты, абоненты, API; работает в Kubernetes.
- **NMS** — веб-админка Orc8r (React + Material-UI v4), мы её не трогаем.
- **Ingest** — наш сервис: собирает измерения и события, пишет `ScenarioFile`.
- **UE / IMSI** — тележка и её сим-карта.

## 7. Два сценария данных

- **A. Просто координаты** (быстрый путь): агент на тележке или GPS-трекер шлёт позицию
  по MQTT/HTTP. Magma не участвует. Карта уже готова, не хватает ingest.
- **B. Позиционирование по LTE** (долгий путь): LTE-модемы, eNodeB, AGW, SIM,
  измерения RSSI/TA, мультилатерация. Требует железа и Magma.

Рекомендация: начинать с A, Magma разворачивать параллельно как лабораторию.

## 8. Дальше по плану

| Этап | Что | Статус |
|---|---|---|
| 1 | Карта на продюсере, живой режим, устаревание | готово |
| 2 | Ingest: приём координат → `ScenarioFile` | следующее |
| 3 | Лаборатория Orc8r (Kubernetes, без AGW) | параллельно |
| 4 | AGW + eNodeB + модемы + мультилатерация | позже |

Минимальная лаборатория Orc8r: один ПК 8 ядер / 16 ГБ / 100 ГБ, Ubuntu 22.04,
k3s или minikube (версия Kubernetes под старые Helm-чарты Magma), Postgres,
сертификаты, Helm-чарт Orc8r. AGW — отдельная машина с двумя NIC.

## 10. Команды и структура

```bash
cd cart-tracker-web
npm test          # 63 теста
npm run build     # tsc -b && vite build
npm run dev       # dev-сервер
npm run live      # продюсер для живого режима (второй терминал)
```

- Карта: `src/features/map/` (MapView, слои, `accuracy.ts`).
- Домен: `src/domain/` (типы, zod-схема, статусы).
- Источники: `src/sources/` (PositionSource, file/, PollingFileSource, registry).
- Демо-данные: `public/data/demo-scenario.json`.
- Правила для агентов: `AGENTS.md` в корне (команды, стиль, границы).

Ограничения среды: `pnpm` не установлен, используется `npm`; `strict` в tsconfig выключен;
документ `docs/data-contract.md` устарел (описывает старый `FleetSnapshot`) — при правках
схемы его нужно привести к `ScenarioFile`.
