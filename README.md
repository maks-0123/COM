# Мониторинг производственных тележек — MVP 0.1

Репозиторий содержит **план и архитектуру первого инкремента**: React-приложение читает координаты тележек из JSON-файла и показывает их точками на карте. Позиции приходят готовыми; RSSI, мультилатерация, Magma и MQTT в этот инкремент не входят.

## Что делает MVP

```
источник координат → fleet.snapshot.json → статический сервер → React SPA → Leaflet
```

1. Внешний процесс пишет полный JSON-снимок и атомарно заменяет файл.
2. Браузер раз в секунду загружает `/data/fleet.snapshot.json`.
3. `FleetRepository` валидирует данные через Zod и возвращает `FleetSnapshot`.
4. Карта рисует станции и точки тележек, показывает точность, метод и статус.
5. При ошибке или устаревании последний хороший снимок остаётся на экране.

## Ключевые решения

- **Файл — не архитектура.** Архитектура — стабильный контракт снимка и заменяемый адаптер источника.
- **Один порт `FleetRepository`.** Сейчас файл, позже HTTP API или WebSocket; карта и домен не меняются.
- **WGS84 в UI, локальные метры — только в движке.** Конвертация выполняется до записи файла.
- **Leaflet + OSM.** Без API-ключа; для закрытого контура — план площадки или свои тайлы.
- **Magma только на сервере.** Браузер никогда не получает учётные данные ядра и не вызывает AGW/Orchestrator.
- **Отказ мягкий.** Битый файл не обнуляет карту; устаревание определяется по `generatedAt`, а не по HTTP 200.

## Быстрый старт (когда появится приложение)

```bash
mkdir web && cd web
pnpm create vite . --template react-ts
pnpm install
pnpm add leaflet react-leaflet @tanstack/react-query zod
pnpm add -D @types/leaflet vitest @testing-library/react @testing-library/jest-dom jsdom
cp public/data/fleet.snapshot.example.json public/data/fleet.snapshot.json
pnpm dev
```

Подробный порядок работ — в главе 9 документа.
