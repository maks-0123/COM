# План MVP — веб-панель мониторинга тележек, этап 0 («файл → карта»)

**Начните отсюда.** Это пошаговый план создания первой версии веб-панели. Ответ на
вопрос *почему* и точные контракты данных — в [ARCHITECTURE.md](ARCHITECTURE.md);
здесь — *что делать, в каком порядке и как понять, что шаг готов*.

Английская версия: [PLAN.en.md](PLAN.en.md).

---

## 0. Цель и рамки

**Цель:** сайт на React, который читает координаты производственных тележек из файла
и показывает их на карте движущимися точками — как автобусы на Яндекс Картах.
Координаты уже вычислены в другом месте (движком позиционирования, симулятором или
скриптом на Python) по затуханию сигнала до двух и более базовых станций. Сайт их
только отображает.

**Входит в этап 0**

- Загрузка файла сценария: площадка, базовые станции, тележки, упорядоченные по
  времени фиксы позиций.
- Проверка файла и понятные сообщения об ошибках, если он некорректен.
- Карта с базовыми станциями (неподвижные значки) и тележками (точки).
- Проигрывание во времени: запуск / пауза / скорость / перемотка; точки плавно
  скользят и показывают направление.
- Для каждой тележки: круг точности, короткий след, статус online/stale/offline,
  значок метода.
- Боковая панель: список тележек с поиском, карточка выбранной тележки.
- Два способа загрузки: встроенный демо-файл или перетаскивание своего файла.
- Работает на уличной карте OSM, **или** на изображении плана цеха, **или** на
  пустой сетке.

**Не входит (следующие этапы):** вычисление позиций по RSSI, бэкенд, база данных,
интеграция с Magma, запросы истории, авторизация, редактирование станций, доводка
мобильной вёрстки.

**Сделано так, чтобы позже:** замена файла на живой поток WebSocket (бэкенд / Magma)
была одним новым классом, без изменений карты и боковой панели. См. ARCHITECTURE §2,
§7, §9.

**Критерий готовности этапа 0:** см. §4 (чек-лист демо).

## 1. Перед началом (≈ 1–2 дня, если стек новый)

Установите:
- **Node.js 20+** (у вас v24 — подходит) и npm.
- **Git**, **VS Code** с расширениями ESLint, Prettier, Error Lens (по желанию).

Изучите ровно столько, сколько нужно (в этом порядке, ~1 час на тему, проходя
туториал руками):
1. **Основы TypeScript:** типы, объединения (union), `type` и `interface`, дженерики
   в общих чертах. → typescriptlang.org, «TS for JS programmers».
2. **React:** компоненты, props, `useState`, `useEffect` (и его функцию очистки!),
   `useRef`. → react.dev, раздел «Learn», первые 3 главы.
3. **Leaflet:** карта, слой тайлов, маркер, круг, ломаная; затем `MapContainer` из
   react-leaflet. → leafletjs.com «Quick Start», react-leaflet.js.org «Getting started».
4. README **zustand** (10 минут) и раздел «Basic usage» README **zod** (15 минут).

Знать не нужно: Redux, Next.js, CSS-фреймворки, бэкенд, Docker (до шага 11 в §3).

### Шаг 2 — Сначала контракт данных (M2)

Это самый важный шаг. От него зависит всё остальное.

**Сделать**
- `src/domain/schemas.ts`: схемы zod для `LocalPoint`, `GeoPoint`, `SiteConfig`,
  `Station`, `Cart`, `PositionFix`, `ScenarioFile` — ровно как в ARCHITECTURE §6.
  Добавить перекрёстные проверки из §6.3 через `superRefine` (совпадение системы
  координат, уникальность id, неизвестный `cartId`, обязательный `origin` для
  local+osm…).
- `src/domain/types.ts`: `export type PositionFix = z.infer<typeof PositionFixSchema>` и т. д.
- Скопировать `examples/scenario.example.json` (лежит рядом с этим планом) в проект как
  `public/data/demo-scenario.json` и `src/domain/__fixtures__/scenario.example.json`.
- `src/sources/file/parsers/parseJsonScenario.ts`:
  `parse(text: string): { ok: true; scenario } | { ok: false; errors: string[] }`.
  Функция выполняет `JSON.parse` (перехватывая синтаксические ошибки), затем zod
  `safeParse`, превращает ошибки zod в строки вида
  `"fixes[3].position: ожидается {x,y}, потому что site.coordinateSystem = local"`
  и сортирует `fixes` по `ts`.
- Тесты: пример файла разбирается; файл с фиксом `{lat,lon}` на площадке `local`
  отклоняется с понятным сообщением; сломанный JSON обрабатывается без падения.

**Готово, когда:** `npm test` показывает ~5 зелёных тестов разбора.

**Осторожно:** не пропускайте `schemaVersion`. Всегда храните `ts` в ISO-8601 **UTC**
(`...Z`). В миллисекунды от эпохи переводите один раз — при разборе.

### Шаг 3 — Геометрические функции (M2/M3)

**Сделать**
- `src/domain/geo.ts`:
  - `localToWgs84({x,y}, origin, rotationDeg)`: повернуть, затем
    `lat = origin.lat + y / 111_320`, `lon = origin.lon + x / (111_320 · cos(origin.lat))`.
    (Плоское приближение; для площадки размером с завод ошибка пренебрежимо мала.)
  - `wgs84ToLocal` (обратная), `distanceM(a, b)`, `bearingDeg(a, b)`.
- `src/domain/interpolate.ts`: `lerpPoint(a, b, t)`, `lerpAngle(a, b, t)` (по
  кратчайшей дуге: 350° → 10° проходит через 0°, а не через 180°).
- Тесты: local→wgs84→local с ошибкой меньше 1 см; азимут (0,0)→(0,10) = 0°,
  →(10,0) = 90°; `lerpAngle(350, 10, 0.5) = 0`.

**Готово, когда:** тесты зелёные.

### Шаг 4 — Показать карту и станции (M3)

**Сделать**
- `src/features/map/projection.ts`: `makeProjection(site)` возвращает
  `{ toLatLng(p: Point): [number, number]; crs: 'EPSG3857' | 'Simple' }` по таблице из
  ARCHITECTURE §6.1.
- `src/features/map/basemaps.tsx`: `osm` → `<TileLayer url=...>` (по умолчанию
  `https://tile.openstreetmap.org/{z}/{x}/{y}.png` с указанием авторства);
  `image` → `<ImageOverlay>` с `CRS.Simple`; `none` → светлая сетка.
- `MapView.tsx`: `MapContainer` на всю область, `preferCanvas`, при загрузке
  подгоняет масштаб под все станции.
- `StationLayer.tsx`: по маркеру на станцию с простым SVG-значком/треугольником и
  всплывающей подсказкой.
- Пока что загрузите демо-файл прямо в `App.tsx` (временно) и передайте станции.

**Готово, когда:** три значка станций стоят в правильном взаимном положении
(BS-1 внизу слева, BS-2 в 200 м к востоку, BS-3 сверху посередине).

**Осторожно (классические ловушки Leaflet):**
- Один раз импортируйте `leaflet/dist/leaflet.css` в `main.tsx`, иначе тайлы
  перемешаются.
- Контейнеру карты нужна явная **высота** (например, `height: 100%` по всей цепочке
  родителей или `100vh`), иначе он будет высотой 0 px и вы ничего не увидите.
- Стандартные значки маркеров под Vite ломаются; используйте `CircleMarker` или свой
  `divIcon`.
- Leaflet использует порядок `[lat, lng]`, а GeoJSON — `[lng, lat]`. Никогда их не
  смешивайте.
- В `CRS.Simple` `LatLng = [y, x]`.

### Шаг 5 — Хранилище и интерфейс источника (M3)

**Сделать**
- `src/sources/PositionSource.ts`: скопировать интерфейс из ARCHITECTURE §7.
- `src/store/trackingStore.ts`: хранилище zustand со структурой из ARCHITECTURE §8.1

  след), `reset`, `setStatus`, `select`, `toggleLayer`.
- `src/app/useSourceConnection.ts`: хук, который создаёт источник по конфигурации
  (`registry.ts`), вызывает `connect()` с обработчиками, пишущими в хранилище, и
  вызывает `disconnect()` в функции очистки эффекта.
- Первая версия `FileReplaySource`: fetch + разбор, `onSite(...)`, затем выдача
  **первого фикса каждой тележки** (без учёта времени).
- `CartLayer.tsx`: по `CircleMarker` на тележку в точке `latest[cartId].curr`.
- Удалить временную загрузку из `App.tsx`.

**Готово, когда:** видны станции и 2 точки тележек; данные идут по цепочке
файл → источник → хранилище → карта.

**Осторожно:** в режиме разработки StrictMode React 18 запускает эффекты **дважды**
(монтирование → размонтирование → монтирование). Если данные загружаются дважды или
появилось два таймера, значит `disconnect()` не убирает за собой. Сделайте его
идемпотентным и отменяйте `fetch` через `AbortController`.

### Шаг 6 — Проигрывание во времени (M4)

**Сделать**
- `src/sources/file/ReplayClock.ts` (чистый класс, `now()` передаётся снаружи):
  `play`, `pause`, `seek`, `setSpeed`, `time()`. Покрыть тестом с поддельными часами.
- `FileReplaySource` реализует `Replayable` (ARCHITECTURE §7.1): такт каждые ~100 мс
  (`setInterval` подойдёт) выдаёт все фиксы с `lastT < ts ≤ clock.time()`, двигая
  индекс; фиксы объединяются в один вызов `applyFixes` на такт; в конце статус
  `ended` (или повтор по кругу).
- Перемотка назад → `onReset()` → выдать по 2 последних фикса каждой тележки до
  нового времени.
- `PlaybackBar.tsx`: показывается, только если `isReplayable(source)`.
  Запуск/пауза, кнопки скорости (1×, 2×, 10×, 60×), ползунок времени по
  `getTimeRange()`, текущее время в формате `HH:mm:ss`. Состояние воспроизведения
  храните в хранилище, чтобы панель и карта не расходились.

**Готово, когда:** после нажатия «play» точки движутся синхронно с подписью времени;
ползунок мгновенно перематывает вперёд и назад; на 60× файл на 30 минут проигрывается
за 30 секунд.

**Осторожно:** не помещайте таймер воспроизведения в React-компонент. Он принадлежит
источнику. Компоненты только читают хранилище.

### Шаг 7 — Ощущение «автобусов на Яндекс Картах» (M5)

**Сделать** (подробности в ARCHITECTURE §8.2–8.3)
- Плавное движение: в `CartLayer` держите в `useRef` словарь экземпляров маркеров
  Leaflet. При новом фиксе запускайте анимацию на `requestAnimationFrame` от текущей
  нарисованной позиции к новой за
  `clamp(Δt_между_фиксами / скорость, 0,2 с, 2 с)` и на каждом кадре вызывайте
  `marker.setLatLng()`. Никакого `setState` на каждом кадре.
- Стрелка курса: маленький повёрнутый треугольник в `divIcon` (CSS
  `transform: rotate(...)`) по `headingDeg` или вычисленному азимуту; замирает, если
  тележка сдвинулась меньше чем на 0,5 м.
- `TrailLayer`: ломаная из последних ~60 точек `trails[cartId]`.
- `AccuracyLayer`: `Circle` радиусом `accuracyM` (в метрах — на OSM `Circle` Leaflet
  принимает метры; в `CRS.Simple` 1 единица = 1 м, что совпадает с нашей проекцией).
- `domain/status.ts`: `online / stale / offline` по возрасту последнего фикса
  относительно **времени воспроизведения**. Стиль точки зависит от статуса.
- Подписи: имя тележки рядом с точкой, скрыто ниже определённого масштаба.
- Цвета: из `cart.color` или из стабильной палитры по порядковому номеру.

**Готово, когда:** на 1× движение выглядит непрерывным (без рывков раз в секунду),
стрелки смотрят вдоль маршрута, у cart-02 из примера появляется большой круг при
переходе на `ecid-ta` и огромный — на `cell-id`.

### Шаг 10 — Генератор демо-данных (M8)

Нужны данные длиннее и реалистичнее, чем написанный вручную пример.

**Сделать**
- `scripts/generate-scenario.ts` (запуск: `npx tsx scripts/generate-scenario.ts
  --carts 20 --minutes 30 --out public/data/demo-scenario.json`):
  - задать 3–5 станций и несколько маршрутов (ломаные между «цехом», «складом» и
    «погрузкой»);
  - каждая тележка едет по маршруту со скоростью 1–3 м/с с остановками, 1 фикс в
    секунду;
  - истинную точку записывать в `truth`; для `position` добавлять шум (например,
    гауссов, σ растёт с расстоянием до ближайшей станции); `accuracyM` ≈ 2σ;
  - иногда переходить на `ecid-ta` / `cell-id` с большим шумом; иногда делать пропуск
    на 40 с (чтобы увидеть `offline`).
- Использовать `domain/geo.ts` и перед записью проверять результат своей же схемой.

Опциональное улучшение (мост к этапу 0.5): вместо шума на позиции вычислять RSSI до
каждой станции по логарифмической модели затухания
`RSSI(d) = A − 10·n·lg(d) + шум` (п. 2.2 системного документа) и сохранять
*измерения*; позже `Locator` в браузере превратит их в фиксы. Тогда вы увидите работу
настоящего алгоритма.

**Готово, когда:** файл на 20 тележек × 30 минут загружается меньше чем за 1 с и
плавно играет на 60×.

## 5. Риски и как план с ними справляется

| Риск | Мера |
|---|---|
| Формат файла постоянно меняется (команда радиочасти ещё экспериментирует) | `schemaVersion` + zod + необязательные поля; адаптер CSV; меняется только парсер |
| Реальные позиции шумные, точки дрожат | Круг точности честно показывает неопределённость; сглаживание (Калман) — задача движка, а не интерфейса; анимация интерфейса уже скрывает шаги в 1 Гц |
| У площадки нет привязки к GPS / работа в помещении | Координаты `local` + подложка-план, широта/долгота не нужны |
| Закрытая сеть, нет тайлов OSM | Настраиваемый `tileUrl`, подложки `image` и `none` |
| Много тележек — карта тормозит | Прямое обновление маркеров, canvas-рендер, пакетная запись; переход на MapLibre изолирован в `features/map` |
| Интеграция с Magma окажется не такой, как ожидалось | Браузер не обращается к Magma; всё поглощает адаптер на бэкенде (ARCHITECTURE §9) |
| Новичок теряется в объёме работ | Каждая веха — самостоятельное демо; можно остановиться после M4 и всё равно иметь работающий продукт |

## 6. Вопросы, которые стоит решить с командой до шага 2

1. **Кто формирует файл и в каком формате?** Согласуйте контракт JSON
   (ARCHITECTURE §6) — или колонки CSV — с теми, кто вычисляет позиции.
2. **Координаты:** движок будет выдавать локальные метры (вероятнее) или
   широту/долготу? Где начало координат площадки и как сетка площадки повёрнута
   относительно севера?
3. **Подложка:** уличная карта (OSM) или план завода? Есть ли план в PNG/SVG с
   известными размерами в метрах?
4. **Масштаб:** сколько тележек и с какой частотой (1 Гц?) в пилоте?
5. **Отображение точности:** показываем круг диспетчерам или только в режиме
   разработчика?
6. **Подтвердите, что «magama» = Magma** (открытое ядро мобильной сети Linux
   Foundation). Если это что-то другое, меняется только ARCHITECTURE §9.
